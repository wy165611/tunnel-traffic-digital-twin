# 可视化人工过线与事件评测

本界面帮助人工建立一个指定运行区间的过线和异常事件真值，不会自动生成真值，不会从“确认报警”复核状态复制完整事件标签。机器事件列表只能显示已触发的事件，无法发现完全漏检；因此必须独立观看完整所选区间。真实演示素材仍是桥梁俯拍视频，当前没有隧道场景精度或真实测速精度结论。

## 操作流程

1. 在“数据导出”打开当前“人工过线 / 事件评测”，或历史行“人工评测”。正在记录的段可以保存草稿；请结束当前段（如开始新段或定位）后再声明完整核验与正式评测。已完成视频的段可直接核验。
2. 使用独立原视频播放器播放、暂停、定位及改变速度。道路叠加始终来自该 run 保存的配置，保持实际视频比例及黑边。上一/下一帧按保存 FPS 近似步进，浏览器和 VFR 解码不保证精确逐帧定位；当前原视频秒数明确显示。
3. 暂停后点击“查询此暂停时间的实际 ID 样本”。读取保存 CSV 的 `observed=true` 样本，选择 0.5 秒以内最邻近实际采样时间，显示原像素底部中心 ID 与列表。不会重新运行检测器、制造检测框或自动生成人工条目。移动时间/播放后，旧查询结果与待返回请求立即作废。
4. 设置位于导出起止时间内的核验区间、核验者和备注。过线按物理车辆穿过保存计数线记录一次，可备注物理车辆，解释系统 ID 分裂/重复计数。点击“记录当前时间过线”；可以手动调整时间、备注或删除。
5. 独立记录异常停车、急减速、逆行事件，时间取达到保存规则条件时刻；同车同类型的重复按保存 cooldown 约定分开记录。先查 ID 映射，ID 必须是此段系统轨迹；完全漏检没有轨迹时留空并填写物理车辆说明。空 ID 的事件保留为漏报，不是匹配任意 ID 的通配符。
6. 勾选确实完整核对的类别，再明确声明完整性。未选择类别是未知；只有选中完整类别后，空数组才表示整段确认没有目标。姓名、类别、区间和任何条目修改后会撤销完整声明；本地更改、待录入输入和旧评测结果均有可见状态。
7. 单独保存草稿或完整文档，再评测精确保存版本。编辑期间不能用旧保存结果冒充当前文档；下载真值和结果携带对应 revision。导入 schema2 JSON 先严格校验同一 run/视频身份/配置/尺寸与字段，再替换本地草稿，并撤销核验状态；每次导入重置分页。关闭未保存内容会先显示保留/放弃选择，重新读取不会覆盖未保存输入。正在读取的旧文件不会覆盖后续导入、编辑、保存或切换后的文档。

浏览器按 run ID、视频内容身份、运行配置指纹与尺寸隔离暂存未提交草稿，包含尚未完成的时间/ID输入和待录入说明。刷新或重开后明确选择“恢复”或“丢弃”，不自动混入服务版本；恢复撤销完整声明。其他窗口已保存时，恢复文档仍保留原 revision，保存冲突后本机内容继续保留，可修正输入并导出、核对服务新版本后重新导入。保存成功或明确丢弃会清除此绑定的本机草稿。浏览器存储不可用时显示警告，离开/刷新另有未保存保护；本机缓存不是服务真值或跨设备备份。记录按钮保存原始视频 PTS，三位小数仅用于显示，避免起止边界舍入出界。

每类最多 1000 条，不会静默截断；姓名最多 100 字、文档备注最多 1000 字、每条物理说明最多 200 字。列表按时间排序，每页 20 条。JSON 导入最大 1 MiB，未知字段、布尔时间/ID、非有限时间、非法区间或跨段绑定均拒绝。观测辅助单个时间最多显示 200 个 ID，超过时明确标记截断。

## 真值与结果契约

独立 `annotations.json` 使用 schema2，包含 run ID、内容身份、保存 scene/calibration/config 的 canonical SHA256 指纹、记录尺寸与独立来源事实、区间、人工来源、revision、时间、过线/事件条目、`reviewed_sections`、`verified` 和 `completeness_confirmed`。`speeds=[]` 配合 `speed_state=unreviewed` 明确表示本界面没有核验速度；不会当作“确认没有速度目标”。

保存使用 expected_revision 检查，冲突时先导出本地草稿再重新打开；原子写独立文档，机器 CSV、不可变截图及报警复核 JSON 均不改写。评测结果单独保存 `evaluation.json`，绑定标注 revision 和运行指纹；下一次编辑保存使旧结果过期，旧版本下载返回冲突。

正式评测只读取已关闭/已完成统计段的一致快照：

- 计数：所选区间含两个边界，以区间末累计流量减区间起点之前的累计流量，和人工过线条目数比较绝对误差。
- 事件：类型、已映射正整数 ID、时间容差共同约束，Hungarian 一对一匹配；空 ID 物理事件不匹配任何预测，进入 FN。显示 TP/FP/FN、precision、recall 和容差。无预测时 precision 不可定义；无真值时 recall 不可定义，不制造 0% 或 100%。
- 未核验类别与速度指标保持 unavailable/null。仅核验计数不会因未核验的车辆/事件 CSV 缺失而失败；所核验类别的 CSV 必须有正确表头和有效值，零字节或错误表头不能视作零目标。
- 不输出整体准确率，不把工作流自测、人工复核数量、演示视频机器计数当成科学精度验证。

现有 schema1 和 `scripts/evaluate.py` 的完整过线/速度/事件契约保持可用；同一 CLI 也可读取 schema2。schema2 优先使用 run 记录的来源尺寸；旧 run 没有尺寸时，必须先通过可验证原视频在界面保存独立来源事实，CLI 不猜测尺寸。

## 来源缺失与旧数据

原视频回放只使用 run 保存的 ID，在 `DATA/videos` 内核验内容哈希，并支持 Range。缺失或改变时禁止原视频回放和新的完整核验声明；已有真值可以读/下载，已有来源事实明确保存后仍可编辑未核验草稿。首次通过真实来源取得的旧 run 尺寸只存独立人工文档，不修改机器 `run.json`；从未取得来源事实的旧 run 若来源也不可用，则显示不可用。

缺少或损坏 run 元数据、道路/参数指纹、来源尺寸或统计时间范围时返回明确不可用/4xx，不伪造默认总数。原视频浏览器不支持时不做整段转码。所有播放、定位、样本查询、保存与评测都不调用实时 /control、视频选择或设置接口。

## 文件与 API

`backend/annotations.py` 负责来源上下文、独立文档、版本与观察辅助，`backend/evaluation.py` 独立 schema2 分支负责部分类别评测；原 schema1 分支保持原契约。`AnnotationDialog`、`RunPlayer`、`RoadOverlay` 与 `manualAnalysis` 负责编辑、播放、坐标和输入/竞态约定。

| 请求 | 用途 |
| --- | --- |
| `GET /api/runs/{run}/annotation-context` | 保存配置、区间与核验条件 |
| `GET /api/runs/{run}/source` | 经过身份核验的独立原视频 |
| `GET /api/runs/{run}/observations?seconds=...` | 最邻近实际观测 ID 辅助 |
| `GET/POST /api/runs/{run}/annotations` | 读取/原子保存独立草稿或真值 |
| `POST /api/runs/{run}/evaluate` | 评测指定保存 revision |
| `GET .../annotations/download?revision=...` | 下载指定保存真值 |
| `GET .../evaluation/download?revision=...` | 下载未过期的指定结果 |

自动化验证使用隔离视频和已保存 CSV：真实跟踪得到 ID/过线并验证独立 Range、草稿持久化、内容变更、机器文件/实时状态不变；手工构造的确定性事件条目检查一对一匹配与未映射 FN。这些是算法契约和流程回归，不构成真实数据人工准确率评估。另覆盖损坏表头、部分类别、schema1原断言、旧来源事实回退、尺寸绑定、版本冲突、空集合比率、输入导入、窄屏 letterbox、刷新草稿恢复/未完成输入、非整数 PTS 边界和异步过期响应。独立浏览器验收由最终交付记录说明。
