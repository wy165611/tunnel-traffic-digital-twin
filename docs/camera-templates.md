# 固定机位命名模板

模板保存的是已保存的图像几何和可选实测标定，不会证明道路实际尺度、相机姿态或视野一致。提供的真实演示视频为桥梁俯拍素材，不能作为已验证隧道机位的证据。

## 工作流程

1. 导入视频，在“道路标定”保存计数线、车道与合法方向；只有有可靠实测尺寸时才保存四点与宽长。未保存道路草稿不能直接创建模板。
2. 侧栏打开“固定机位模板”，填写名称与备注，点击“保存为命名模板”。后端只捕获此刻已保存道路，不读取前端草稿。保存、列出、重命名、删除、预览都不会暂停或重建实时分析。
3. 切换到目标视频后再打开模板管理，选择模板。独立预览叠加目标视频与映射后的计数线、车道、标定点；按实际画面比例保留黑边，坐标不会因容器大小变形。
4. 核对同机位、视野和图像边界。宽高比差异超过 1% 时只允许预览，必须在当前画面重新绘制；尺寸或比例相同也不能证明未裁切、旋转、移动、变焦。
5. 默认“仅应用几何”清除目标真实尺度，世界坐标、速度、加速度和速度规则回到未标定状态。模板包含可靠实测标定且同机位、同视野、实际宽长仍有效时，才勾选第二个独立确认框复制尺度；不会从图像分辨率推算米数。
6. 点击应用才结束当前统计段并保存目标道路，旧 CSV 保留。编辑面板仍打开时禁止应用，保护其中的道路或参数草稿。切换模板、模板版本、目标视频或道路修订后，所有确认自动清空。

目标按内容身份保存配置，重新选择/重启后仍生效。删除模板不会撤销已经应用到视频的配置。应用记录包括模板 ID/版本、来源、几何与尺度确认及时间，进入目标道路与后续 run 元数据；普通道路保存会清除旧模板确认，避免新绘制冒用旧机位确认。

## 坐标和存储约定

同宽高比的点按 `x * target_width / source_width`、`y * target_height / source_height` 映射；物理宽度和长度原值保留，只能由人工明确确认。比例误差为 `abs(target_ratio / source_ratio - 1)`，允许不超过 0.01（含浮点边界容差）。比例不同的映射仅供预览，应用始终被后端拒绝。

数据单独存于 `DATA/camera_templates/<32hex-id>.json`。文件名由服务器生成，名称不能形成路径；名称去除两端空白、不能为空、最多 60 字且不区分大小写唯一，备注最多 1000 字，最多 100 个模板。模板为原子、版本化 JSON，场景/标定是深拷贝。超过 256 KiB、损坏或不符合基本版本结构的存储文件不会被当成有效模板使用。

新增 API：

| 请求 | 行为 |
| --- | --- |
| `GET /api/camera-templates` | 列表 |
| `POST /api/camera-templates` | 保存当前已保存道路，携带目标 token/scene_revision/name/note |
| `POST /api/camera-templates/{id}/rename` | 名称、备注更新，携带 revision |
| `POST /api/camera-templates/{id}/delete` | 删除，携带 revision |
| `POST /api/camera-templates/{id}/preview` | 校验目标与模板版本，返回映射/适用条件 |
| `POST /api/camera-templates/{id}/apply` | 再校验版本、目标和人工确认，再按正常道路保存 |

所有模板写入与应用采用固定服务锁顺序；应用的目标/模板版本检查与道路提交处于同一临界区。另一窗口重命名、删除、换视频或保存道路后，陈旧请求会返回冲突，而不会把旧预览应用到新目标。

`backend/camera_templates.py` 负责存储、命名与映射，`backend/service.py` 的共享锁内道路保存负责实际提交；`CameraTemplatesDialog` 和 `RoadOverlay` 负责界面与独立叠加。测试覆盖 CRUD/重启、保存而非草稿、深拷贝、不修改实时会话、同比例与 1% 边界、不同宽高比、默认清尺度、显式复制尺度、内容持久化、来源记录清除、坏文件、安全 ID、并发修订和无死锁。
