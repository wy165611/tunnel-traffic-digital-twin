## 1. Named saved camera templates
Store versioned atomic JSON under isolated DATA/camera_templates (server-generated 32-hex ID; names never form paths). List, create from CURRENT SAVED scene/calibration, rename and delete; enforce trimmed nonempty bounded names and notes, unique names and bounded files, safe IDs, locking and revision conflict detection. Save source identity/dimensions, immutable scene/calibration snapshot, creation/update timestamps and template revision. Saving/listing/previewing templates must not close or mutate the live run. Unsaved road drafts cannot silently become saved templates; UI directs save road first or clearly captures only saved road.

Preview endpoint validates current video_token and scene_revision and template revision, returns mapped scene/calibration and source/target dimensions plus applicability/reasons. Coordinate contract: source pixel coordinates map via x*targetWidth/sourceWidth, y*targetHeight/sourceHeight only when original aspect ratios match within explicit 1% tolerance; different aspect ratio is PREVIEW ONLY, apply blocked with draw-again guidance. Equal ratio or dimensions do NOT prove same camera/FOV, crop, rotation or zoom.

UI: clear named template manager entry (toolbar/sidebar or saved road section), create with name, list/rename/delete, select and overlay on current video with actual aspect preserved, labelled counting line, lanes and optional calibration points. Preview is local/independent and nonmutating. Confirm geometry/camera view manually before apply. Default geometry-only application CLEARS real scale on target, explicitly warns uncalibrated speed. Optional scale copy only when template has measured calibration and a separate unchecked-by-default same-camera/same-FOV/still-valid-actual-width-length confirmation is checked; selecting template/target change clears confirmations. Changed ratio cannot copy scale. No automatic physical scaling from dimensions. Apply revalidates template revision + target token + scene revision on server, runs SceneInput/RoadCalibration/bounds, persists through normal scene-save behavior under service lock, closes current segment only on explicit APPLY; preserve old CSVs. Record applied template ID/revision/source/confirmation/time provenance in target/run metadata. Template scale disabled or missing => calibration None; no ghost calibration from previous target. Do not let another window's template rename/delete or road/video change race an old preview into application. Saved target config survives select/restart; deleting template does not undo applied target.

## 2. Run-bound human annotation contract and independent player
Introduce version-2 annotation truth bound to run_id, video_identity and deterministic canonical fingerprint of run's saved scene/calibration/config (not current live config), recorded dimensions, interval, annotator, revision and timestamps. Manual crossings and events arrays are INDEPENDENT of machine event review. reviewed_sections is a subset of crossings/events; speeds are explicitly unreviewed/unavailable in this UI. Preserve schema-1 evaluator/CLI unchanged. No auto-copy confirmed machine alarms as complete truth.

Endpoints suggested: GET/POST `/api/runs/{run}/annotations`, GET `/api/runs/{run}/annotation-context`, GET `/api/runs/{run}/source`, GET `/api/runs/{run}/observations?seconds=...`, POST `/api/runs/{run}/evaluate`, GET annotation JSON/result JSON downloads. Actual naming may differ if cohesive and documented. Use run_directory validation, bounded payloads, atomic separate annotation JSON, expected annotation revision to reject stale saves, strict schema validation/finite seconds/positive integer or explicit null event vehicle IDs/supported types/interval within exported bounds. Reject other run/identity/fingerprint imports. Do not modify machine CSVs, immutable evidence or existing reviews.

Only completed/closed saved segments may generate formal metrics; active/recording context indicates finish analysis first. Use saved source identity and dimensions (legacy derive dimensions from verified original video if possible; unknown remains unavailable). Missing/corrupt legacy metadata or required CSV produces explicit unavailable/4xx, never HTTP500/fake totals. Source absent/changed forbids original playback and NEW complete-verification claims while saved annotation can be viewed/exported and incomplete draft edited. Stored previously verified truth can still be read; no invented source.

Provide an independent native video player sourced by run with Range and hash validation, playback rate, pause and seek, frame-step controls using recorded fps/currentTime when supported, explicit current video seconds. Never call live /control/seek/select/settings from annotation; render recorded run's counting line/lanes as a scaled SVG/canvas overlay on this video's actual letterboxed display. Use ResizeObserver/object-fit sizing correctly for wide/tall/small views. A paused-time observation helper reads saved observed=true vehicle CSV samples near the time (nearest timestamp, clearly labelled actual sample time and pixel bottom-center IDs). It does NOT rerun detector or invent boxes/truth; show ID markers/list to support event mapping, with empty/unavailable states and read-only run-specific facts. Do not fire unbounded whole-CSV reads each playback frame: user-triggered paused-frame lookup or debounced bounded access is sufficient.

Editor: interval start/end (valid export endpoints by default), annotator, optional note, record one crossing at current video time, record supported event at current time with run-specific vehicle ID (or explicit no-track mapping) and explanatory hint; manual time adjustment, remove rows, display sorted bounded/paginated list. Allow independent missed-event entries. For crossing keep optional physical vehicle note to support one-physical-vehicle/system-one-ID counting explanation. Event UI must explain all three types and repeated/cooldown convention. For an independently observed missed event with no system track, vehicle_id is null and a nonempty physical_vehicle_note is required. UI labels it unmapped/missed; it remains in truth count and FN, never wildcard matches a prediction. Existing mapped IDs remain positive integers. Rows are manual inputs, not generated from alarms. Category checkboxes explicitly state COMPLETE interval verified for count/events. Unselected category is unreviewed, even if arrays are empty. Overall verified=true requires named annotator + at least one completed category + explicit manual completeness declaration. Any changes to interval/items/annotator/completed categories revoke verification (draft); unsaved changes must be visible, not lost on report switch or refresh. Save draft separate from Evaluate. Reload/restart restores document. Optional JSON import/export supports schema2, only same bindings; import resets verification for explicit reconfirmation. If import added, validate before replacing existing draft. Max row/note payload limits documented; no silent truncation.

Formal evaluation reads the saved verified document and consistent CLOSED run snapshot, binds specific run/geometry/config; rejects unverified, stale revision/bindings/incomplete interval or unsupported values. Partial-category results mark unavailable rather than zeros; speed fields null/unavailable and explain not evaluated. Counts compare cumulative differences under existing inclusive interval semantics; events with mapped IDs keep existing Hungarian one-to-one type+vehicleID+time-tolerance matching; null-ID truth events never match and count as FN, output TP/FP/FN, precision/recall; zero truth yields recall null, zero predicted yields precision null. Return count absolute error and clear matching tolerance; no overall accuracy claim. Persist evaluation result with annotation revision/fingerprint so edit invalidates prior result; display stale result warning and require reevaluate. UI must NOT treat a late old evaluation response as current after edit/save/target switch. Download exports are bound to the exact saved truth/result revision and explain unknown categories. Existing schema1 full-speed CLI stays usable.
