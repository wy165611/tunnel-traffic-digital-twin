# 孪生道路方向检查

日期：2026-10-01。

未标定视图原来将横向限制在 80–320px、纵向填满画布，导致道路比例失真；没有车道配置时还绘制了四条竖向默认车道。现在图像坐标按原视频宽高比例统一缩放，保留完整画面范围，车道、计数线、车辆和轨迹共用映射。没有车道配置时仅显示图像范围。标定视图保持米尺度等比例，显示方向根据标定角点调整，车道方向和车辆朝向采用相同变换。

## 当前横向视频配置

`7c370e40-13454593_3840_2160_60fps.mp4` 为 3840×2160 横屏视频。依据首帧的可见车道线，手工描绘上方两条左行、下方两条右行的机动车道。配置通过现有 `/api/calibration` 保存到 `backend/data/calibrations/50402aaca3607bdc2042a455-scene.json`，可在界面继续编辑。未添加真实尺度或计数线。

这些是人工图像轮廓，未声称自动识别道路，也不代表实测距离。其他未配置的新视频保持图像比例，需要按各自画面绘制车道。

## 验证结果

- `npm --prefix frontend run build` 通过 TypeScript 和 Vite 生产构建。保留原有 ECharts 分包大小提示。
- `npm --prefix frontend test`：8 项通过，覆盖横/竖屏的桌面和手机比例、车辆与横向车道/计数线对齐、透视标定与世界坐标一致、旋转/斜向道路的朝向和等比例距离。
- `.venv/bin/python -m pytest -q`：24 项通过。
- 实际生产页面 `http://127.0.0.1:8000`：选择用户提供的横屏视频，重新分析并暂停，车辆显示在相应横向车道内，轨迹方向与视频一致；重新选择视频仍会加载已保存的四条车道。
- 原有 2160×3840 竖屏演示的六条车道和计数线仍按视频方向显示。
- 1440px 桌面、390px 和 320px 手机检查通过，手机双面板上下排列，没有页面整体横向溢出。浏览器控制台未记录错误或警告。
